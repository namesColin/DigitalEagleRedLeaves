## 一、项目概述

**数字鹰红叶**是一个本地化 AI 数字生命项目。目标是创造一个名为"红叶"的数字存在，具备长期记忆、视觉感知和个性化人格。最终形态为 VTube Studio 桌宠。

### 核心设计理念

- **全本地化基础**：Embedding、Reranker、视觉模型本地运行；LLM 支持 DeepSeek API / 本地 Ollama 一键切换
- **神经元记忆**：基于图数据库的语义记忆网络，模拟人脑联想机制
- **微服务架构**：视觉模块独立部署为 FastAPI 微服务，可复用于不同项目

## 五、核心模块实现细节

### 5.1 Config 双开关（`config.py`）

```python
class Config:
    LLM_BACKEND = "deepseek"           # 对话 LLM
    GRAPHITI_LLM_BACKEND = "deepseek"  # Graphiti 实体提取 LLM（独立）

    # 两个切换共享同一组预设值
    DEEPSEEK_BASE_URL / DEEPSEEK_API_KEY / DEEPSEEK_MODEL
    OLLAMA_BASE_URL  / OLLAMA_API_KEY  / OLLAMA_MODEL

    # Embedding & Reranker 始终 Ollama（DeepSeek 不提供）
    EMBED_BASE_URL / EMBED_API_KEY / EMBED_MODEL / EMBED_DIM
    RERANK_BASE_URL / RERANK_API_KEY / RERANK_MODEL
```

`_pick(backend)` / `_pick_key(backend)` / `_pick_model(backend)` 三个助手消除重复代码。
`resolve_*()` 给对话 LLM，`resolve_graphiti_*()` 给 Graphiti LLM。

### 5.2 记忆引擎（`brain_engine.py`）

```
HongYeBrain
├── initialize()
│   ├── 创建 graphiti_llm_client（跟 GRAPHITI_LLM_BACKEND）
│   ├── 创建 chat_llm_client（跟 LLM_BACKEND）
│   ├── [DeepSeek] _patch_graphiti_for_deepseek()
│   ├── 创建 embedder + reranker（始终 Ollama）
│   └── 初始化 Graphiti(Neo4j)
│
├── add_memory(content, source)
│   └── graphiti.add_episode() → LLM 实体提取 → 写入 Neo4j
│
├── search_memory(query)
│   └── graphiti.search() → 返回去重后的 fact 列表
│
├── check_semantic_exists(content, threshold=0.85)
│   ├── search_memory() → 获取已有记忆
│   ├── 逐条 embedding + 余弦相似度
│   └── 超过阈值 → 判定重复
│
└── close()
```

**语义去重性能**：需 N+1 次 embedding 调用（N = 已有记忆数），是最耗时的操作。

**Embedding 兼容层**：`get_embedding()` 兼容 4 种接口（`embed_documents` / `create_batch` / `create` / `client.embeddings.create`）。

### 5.3 DeepSeek 适配补丁（`_patch_graphiti_for_deepseek`）

**问题**：Graphiti 调用 LLM 时发送 `response_format: {type: json_schema, ...}`，DeepSeek API 不支持。

**解决**：运行时 monkey-patch `OpenAIGenericClient._generate_response`：
1. 拦截 `response_model` 参数，强制传入 `None`
2. 将 `json_schema` 降级为 `json_object`
3. 将 JSON Schema 文本注入最后一条 message，确保 LLM 输出正确字段名
4. 注入 "Respond in JSON format" 满足 DeepSeek 要求

仅当 `GRAPHITI_LLM_BACKEND == "deepseek"` 时激活。切到 `"ollama"` 不触发。

### 5.4 人格系统（`personality.py`）

```
HongYePersonality
├── chat(question)
│   ├── brain.search_memory(question) → 检索相关记忆
│   ├── _build_prompt(context, question) → 人格化 Prompt
│   └── brain.chat_llm_client.chat(prompt) → 流式输出
│
└── remember_dialogue(content, source)
    ├── brain.check_semantic_exists(content)
    └── brain.add_memory(content, source)
```

每次对话后，用户的话和红叶自己的回复都会被记住。

### 5.5 视觉模块

C/S 架构：

```
vision_server.py (FastAPI, port 30001)
  POST /analyze?prompt=<OCR_WITH_REGION>
    ← image (PNG bytes)
    → {data: {prompt: {labels: [...], quad_boxes: [[...]]}}}

vision_client.py        → 截屏 → API → JSON 结果
vision_debug_view.py    → 同上 + 绿框标注 + 保存 PNG
```

Florence-2 支持的 prompt：`<OCR>` / `<OCR_WITH_REGION>` / `<OD>` / `<DETAILED_CAPTION>`。

### 5.6 人格播种（`scripts/seed_personality.py`）

```
循环：
  search_memory() → 获取已有人格记忆
  DeepSeek 根据记忆生成下一个访谈问题
  用户回答
  check_semantic_exists() → 去重检查
  add_memory(content=answer, source="Main-Brain")
```

`source="Main-Brain"` 标记为核心人格记忆，区别于普通对话记忆。

## 六、技术踩坑

| 问题 | 原因 | 解决 |
|------|------|------|
| DeepSeek `json_schema` 报 400 | Graphiti 用 `json_schema` 做结构化输出，DeepSeek 不支持 | 运行时 patch 降级为 `json_object` + schema 注入 prompt |
| DeepSeek `json_object` 要求 prompt 含 "json" | DeepSeek API 校验规则 | patch 中自动在 prompt 末尾注入 `Respond in JSON format` |
| `git dubious ownership` 错误 | 仓库目录所有者 ≠ 当前用户 | `git config --global --add safe.directory` |
| Ollama 模型缺失导致 Graphiti 失败 | 只有 embedding/reranker 无对话模型 | `ollama pull qwen3:8b` |
| 项目结构平铺难以维护 | 早期快速迭代积累 | 按逻辑层次重组为 src/core、src/vision、src/tools |
