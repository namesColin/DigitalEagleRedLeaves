# 桌面自动化模型调研报告

> 日期：2026-07-13
> 目的：寻找能可靠完成"看懂屏幕 → 输出精确坐标"的模型

---

## 一、核心结论

**OmniParser V2 的开放式检测 + 通用 VLM 推理方案，在 2026 年 7 月无法实现可靠桌面自动化。** 不是因为代码或 prompt 设计不好，而是 OmniParser 的检测覆盖度和标签细度不够。

**替代方案存在**——有专门为 GUI 自动化训练的模型，ScreenSpot Pro 基准上得分远超通用方案。

---

## 二、ScreenSpot Pro 基准对比（GUI 元素定位精度）

| 模型 | ScreenSpot Pro | 类型 | 可用性 |
|------|:---:|------|------|
| **Qwen3.7-Plus** | **79.0** | 混合 Agent API | DashScope API，$0.40/M tokens |
| **UI-TARS-1.5-72B** | **61.6** | 专训 GUI Agent | 开源（Apache 2.0），本地部署 |
| **UI-TARS-1.5-7B** | **49.6** | 专训 GUI Agent | 开源，本地 7B 可跑 |
| OmniParser V2 (纯检测) | 39.6 | 检测工具 | 本地 |
| Claude 3.7 | 27.7 | 通用 VLM | Anthropic API |
| OpenAI CUA | 23.4 | 通用 VLM | OpenAI API |
| Qwen-VL-Max（我们当前） | ~30 | 通用 VLM | DashScope API |

我们当前方案的精度在最底层。**Qwen3.7-Plus 得分是 Qwen-VL-Max 的 2.6 倍。**

---

## 三、推荐候选

### 方案 A：Qwen3.7-Plus API（最快验证，30 分钟）

| 项目 | 值 |
|------|-----|
| 端点 | `dashscope-intl.aliyuncs.com/compatible-mode/v1` |
| 模型名 | `qwen3.7-plus` |
| 输入价格 | $0.40 / 百万 token |
| ScreenSpot Pro | **79.0** |
| 输出格式 | 原生像素坐标 `click(x=487, y=232)` |
| 改动量 | 改 config.py model 名 + 简化 prompt |

**关键差异**：Qwen3.7-Plus 不是通用 VLM——它是专门为 GUI 操作训练的混合 Agent 模型。输入截图直接输出精确操作坐标，不需要 OmniParser。**用我们的 DashScope API Key 就能调。**

### 方案 B：UI-TARS-1.5-7B 本地部署（半天）

| 项目 | 值 |
|------|-----|
| 参数 | 7B，~14GB VRAM（量化后 8GB 可跑） |
| 许可 | Apache 2.0 |
| ScreenSpot | 49.6（专训模型，远超通用 VLM） |
| 输入输出 | 截图 → 操作坐标 |
| 部署 | `pip install ui-tars` + HuggingFace 下载权重 |

**优势**：完全本地，不依赖 API。**劣势**：需要 8GB+ 显存，首次部署较复杂。

### 方案 C：Claude Computer Use（1 小时）

| 项目 | 值 |
|------|-----|
| OSWorld 成功率 | **72.1%**（端到端任务） |
| 可用性 | Anthropic API（额外付费） |
| 优点 | 最成熟的端到端方案 |
| 缺点 | 贵，需要 Anthropic API Key |
