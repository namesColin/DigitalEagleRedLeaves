## 一、现状诊断

### 1.1 当前架构

```
pyautogui 截屏 → FastAPI HTTP → Florence-2-large (0.7B) → JSON 返回坐标+标签
```

### 1.2 发现并修复的问题

**问题一：推理极慢** — 原始 `<OCR_WITH_REGION>` 耗时 672s（11 分钟）。

根因：`num_beams=3` + `max_new_tokens=1024` + `use_cache=False`（Florence-2 代码 bug，不能开 cache）。

| prompt | 修复前 | 修复后 |
|--------|--------|--------|
| OCR | 672s | 4.02s |
| OD | 3.57s | 0.26s |
| Caption | 崩溃 | 0.61s |

**问题二：坐标双重转换** — `post_process_generation(image_size=...)` 已转像素，debug_view 又乘一遍。修复：去除归一化乘法。

**问题三：27 框重叠** — Florence-2 无 NMS。修复：添加 IoU 去重（阈值 0.5）。

**问题四：标签乱码** — `</s>` `<s>` token。修复：渲染前清洗。

### 1.3 Florence-2 根本局限

非 UI 专用：标签是 "x"、"×" 而非 "close button"，无 NMS，无空间关系理解。

## 三、OmniParser V2 调研详情

### 3.1 内部结构

不是 pip 包，是微软开源项目 ([microsoft/OmniParser](https://github.com/microsoft/OmniParser))：

```
OmniParser V2
├── icon_detect    →  YOLOv8（ultralytics 加载）
│    └── 权重: icon_detect/model.pt (~40MB)
└── icon_caption   →  Florence-2 base（UI 微调）
     └── 权重: icon_caption_florence/ (~0.5GB)
```

两个都可直接 import 调用，不需要 Gradio。

### 3.2 集成设计

```
不改: vision_server.py（FastAPI）、vision_client.py（截屏+请求）

新增: vision_model_v2.py → VisionModuleV2
  ├── YOLOv8 检测    → {boxes: [[x1,y1,x2,y2],...]}
  ├── Florence-2 描述 → {labels: ["A play button", ...]}
  └── 输出            → JSON 兼容 V1 API

切换: vision_server.py 改 MODEL_VERSION = "v1" / "v2"
```

## 四、实施日志

### 4.1 安装依赖

```bash
pip install ultralytics
# ✅ 成功，CUDA 可用
```

### 4.2 下载模型权重

HuggingFace 直连 SSL 错误 → 使用镜像 `hf-mirror.com` 成功下载（1m37s）。

### 4.3 创建 vision_model_v2.py

**踩坑 1：`attn_implementation` 缺失**

Florence-2 自定义代码在新版 transformers 下需要 `attn_implementation="eager"`。V1 有此行，V2 初版遗漏。

修复：`AutoModelForCausalLM.from_pretrained(..., attn_implementation="eager", dtype=self.dtype)`

**踩坑 2：通用 Florence-2-large 做 caption 效果差**

初版用已有的 `Florence-2-large` 为每个检测框生成描述，结果全是视觉风格："a black background with..."。OmniParser 的 `icon_caption_florence` 是在 UI 数据上微调过的，能输出功能性标签。

修复：改用 OmniParser 微调权重加载 caption 模型。

**踩坑 3：icon_caption_florence 离线加载失败**

`config.json` 的 `auto_map` 指向 `microsoft/Florence-2-base-ft`（远程 HF），`trust_remote_code=True` 触发联网下载 `configuration_florence2.py`，SSL 错误。

修复：
1. 从 HF 缓存复制 `configuration_florence2.py`、`modeling_florence2.py`、`processing_florence2.py` 到本地模型目录
2. 改 `config.json` 的 `auto_map` 从远程 HF 路径 → 本地文件名
3. 改 `_name_or_path` 避避免 transformers 误判

**踩坑 4：81 个框太多导致慢**

初始 `conf=0.05` 产生 100+ 框，逐个 Florence-2 caption 耗时 25s+。

修复：提高 YOLO conf 阈值到 0.15，框降到 81 个，速度 7s。

### 4.4 适配 vision_server.py

新增 `MODEL_VERSION` 切换变量，一行改 "v1"/"v2" 即可切换模型。

### 4.5 适配 vision_diagnose.py 和 vision_debug_view.py

V2 的 JSON 格式与 V1 不同：
- V1: `{"data": {"<OCR>": {"bboxes": [...], "labels": [...]}}}`
- V2: `{"data": {"boxes": [...], "labels": [...], "format": "xyxy_pixel"}}`

修复：两个客户端都加上 V1/V2 兼容判断。

坐标格式差异：V1 bboxes 是 `[y1,x1,y2,x2]`，V2 是 `[x1,y1,x2,y2]`。debug_view 的 IoU 合并函数加上 `is_v2` 标志正确解析。

## 五、最终对比

| 指标 | V1 (Florence-2-large) | V2 (OmniParser YOLO + 微调 F-2) |
|------|----------------------|----------------------------------|
| OCR 速度 | 4.02s | 7.06s |
| OD 速度 | 0.26s | 5.01s |
| Caption 速度 | 0.61s | 0.67s |
| 检测框数 | 27（严重重叠） | 81（NMS 已去重） |
| 标签质量 | `</s>x`, `×` | `A play button`, `A folder`, `Vision Diagnose.Py.` |
| 标签语义 | ❌ 单字符 | ✅ 功能描述 |
| 重叠框 | ❌ 需后处理 IoU | ✅ YOLO 内置 |
| 离线可用 | ✅ | ✅（修复后） |

### 速度差异分析

V2 比 V1 的 OD 慢是因为架构不同：
- V1 OD：Florence-2 一次 forward pass 输出 1 个 "computer monitor" 框
- V2：YOLO 先检测 81 个图标，再为每个图标做 Florence-2 caption（批量 16 个/次，约 5 轮推理）

如果不需要为每个框做 caption，纯 YOLO 检测只需 ~0.3s。
