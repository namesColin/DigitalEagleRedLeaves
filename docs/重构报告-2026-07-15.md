## 二、重构二：CDP 模式去 pyautogui

### 改前

```
每步: pyautogui.screenshot() → 100次像素采样对比 → Changed判断
      → Chrome必须在前台 / 被覆盖就误判 / 每步截整张桌面
      → asyncio.sleep(1) 硬等
      → DeepSeek 不知道自己在哪 → 反复 navigate
```

### 改后

```
每步: cdp.get_page_info() → 读 URL+title
      → 对比前后 URL/title → Changed判断
      → Chrome 前后台均可 / O(1) 操作
      → 无 sleep(1)
      → DeepSeek prompt 含 "Current page: URL | Title" → 不重复 navigate
```

### 新增能力

| chrome_driver 方法 | 作用 |
|--------------------|------|
| `get_page_text()` | `document.body.innerText` → LLM 理解页面内容，零视觉 |
| `get_page_info()` | `{url, title}` → 验证+上下文 |
| `screenshot()` | `Page.captureScreenshot` → 仅视觉兜底，仅截浏览器视口 |

### 速度对比

| 指标 | 改前 | 改后 |
|------|------|------|
| 验证方式 | pyautogui 截屏+像素采样 | CDP URL/title 对比 |
| Chrome 需前台 | 是 | 否 |
| 硬等待 | sleep(1) | 无 |
| 重复导航 | 经常 | 已消除 |
| 验证耗时 | ~0.6s | ~0.3s |

## 三、验证结果

**百度搜索"天气"**：7步完成，6次CDP，0次视觉
```
navigate → click搜索框 → type天气 → press Enter → done ✅
```

**B站搜索"推理视频"**：
```
navigate B站 ✅ → click搜索框 ✅ → type推理视频 ✅ → press Enter ✅
→ click第一个视频 ⚠️ (匹配失败, DeepSeek描述太模糊)
```

### 当前瓶颈

`_match_element` 对模糊描述（"第一个视频"、"first video in results"）匹配成功率低。搜索结果页的元素列表里每个 `<a>` 标签都是视频标题，DeepSeek 需要知道"选第一个就行"而不是找名字叫"第一个"的元素。

### 建议后续优化

1. `_get_intent` 增加提示："To click the first item in a list, just describe what it IS, not that it's 'first'. E.g. click('a video title link') not click('the first video')."
2. `_match_element` 如果找不到精确匹配，回退到选列表里第一个输入/第一个链接
3. 把 `get_page_text()` 结果（页面文字）喂给 `_match_element`，让 DeepSeek 理解页面上下文
