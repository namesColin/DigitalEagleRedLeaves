# 记忆模块架构分析：Graphiti 写 + Cypher 读

> 日期：2026-07-12

---

## 结论

**Neo4j 是合适的记忆模块工具，Graphiti 也没选错。** 问题是 Graphiti 的 `search()` 被当成了读接口，但它不暴露图结构。应该 Graphiti 负责写（实体提取 → 自动建图），Cypher 负责读（BFS 联想检索 + 随机扰动）。

---

## Graphiti 写入过程

`add_episode("红叶喜欢在深夜观测数据流动")` 触发的内部流程：

### ① LLM 实体 & 关系提取

```
输入 → LLM → {
  "entities": [
    {"name": "红叶",    "entity_type": "Person"},
    {"name": "深夜",    "entity_type": "Time"},
    {"name": "数据流动", "entity_type": "Concept"}
  ],
  "relationships": [
    {"source": "红叶", "relation": "喜欢", "target": "深夜"},
    {"source": "红叶", "relation": "观测", "target": "数据流动"},
    {"source": "深夜", "relation": "时间段_发生", "target": "数据流动"}
  ]
}
```

### ② 写入 Neo4j 图

```
    (红叶:Entity) ──[喜欢]──→ (深夜:Entity)
         │                       │
         │                  [时间段_发生]
         │                       │
         └──[观测]──→ (数据流动:Entity)
```

每个节点附带 name、summary、entity_type、embedding 向量。

---

## 问题：Graphiti search() 不暴露图

```
graphiti.search("深夜")
  → 向量找最近 Entity 节点
  → 返回 name/summary 拼成的文本列表
  → 图结构（边、邻接节点）全丢失
```

**效果**：买的图数据库只当文本仓库用。

---

## 方案：Cypher 读，Graphiti 写

### 核心节点 → BFS 联想检索

```cypher
-- 1. 定位核心节点（可结合向量）
MATCH (core:Entity {name: "深夜"})

-- 2. BFS 2 层，按距离排序
MATCH path = (core)-[*1..2]-(neighbor:Entity)
RETURN
    core.name        AS 核心记忆,
    neighbor.name    AS 联想记忆,
    length(path)     AS 关联距离
ORDER BY length(path)
```

**输出**：

```
核心: 深夜
  ├── 距离1: 红叶         (直接关联)
  ├── 距离1: 数据流动      (直接关联)
  ├── 距离2: 观测          (经由红叶间接关联)
  ├── 距离2: 摇滚乐        (红叶的其他"喜欢"关系)
  └── 距离2: 宇宙          (红叶的其他"观测"关系)
```

### 随机扰动（非稳定性记忆）

```cypher
MATCH path = (core)-[*1..2]-(neighbor:Entity)
WHERE length(path) >= 1
RETURN neighbor, length(path)
ORDER BY
    CASE WHEN rand() < 0.2
         THEN rand()          -- 20% 随机打乱
         ELSE length(path)    -- 80% 正常按距离
    END
```

### 记忆错位（偶尔插入无关节点）

```cypher
CALL {
    -- 正常联想
    MATCH path = (core)-[*1..2]-(neighbor:Entity)
    RETURN neighbor, length(path) AS dist
    UNION
    -- 随机错位（概率触发）
    MATCH (random:Entity) WHERE random <> core
    RETURN random AS neighbor, 99 AS dist
    LIMIT 1
}
```

## 架构对比

| | Graphiti `search()` | Cypher BFS（方案） |
|---|---|---|
| 返回结构 | 一维文本列表 | 带距离的图节点网 |
| 联想 | ❌ | ✅ BFS 邻接扩散 |
| 距离感知 | ❌ | ✅ `length(path)` |
| 随机扰动 | ❌ | ✅ `ORDER BY rand()` |
| 层次化记忆 | ❌ | ✅ 距离分层 |
| 写入建图 | ✅ Graphiti | ✅ Graphiti（保留） |

---

## 最终架构

```
写入：文本 → Graphiti.add_episode() → LLM 提取实体/关系 → Neo4j 节点+边
读取：查询 → 向量定位核心节点 → Cypher BFS → 联想记忆列表
      └── 可选：随机扰动 / 距离分层 / 重要性过滤
```

Graphiti 的价值在写入自动化（省去手写实体提取 prompt），Neo4j 的价值在图遍历。各用所长。
